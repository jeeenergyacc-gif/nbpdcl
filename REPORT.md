# NBPDCL Power Purchase Dashboard — Delivery Report

## Summary

Integrated the two uploaded chart concepts — the **3D pseudo-extruded Donut**
and the **SVG Energy Sunburst** — into the existing `PowerPurchaseDashboard.tsx`
as two new, fully data-driven components. Both now render from the dashboard's
live React Query hooks (`usePurchaseDistribution`, `usePurchaseSunburst`) — no
hardcoded numbers remain. The project builds cleanly end-to-end
(`tsc -b && vite build`) with zero TypeScript/build errors.

## Audit findings (before changes)

- Project is a Vite + React 19 + TypeScript frontend and a FastAPI backend
  reading from Google Sheets, already wired together correctly via
  `src/api/purchaseApi.ts` → `/purchase/*` FastAPI routes → `purchase_analytics.py`.
  This layer was **not modified** — contracts, filters, and caching all work
  as before.
- Found stray, broken directories in `frontend/src` **and** `backend/app` —
  literal folders named `{api,components` /
  `{api,components/{layout,cards,charts,filters,common},pages...}` (frontend)
  and `{api,core,services,models}` (backend) — leftovers from an unexpanded
  `mkdir -p src/{a,b,c}` brace-expansion run under a non-bash shell. All were
  empty and unreferenced; removed.
- `frontend/tsconfig.tsbuildinfo`, `frontend/dist/`, and `node_modules/` build
  artifacts were present in the uploaded archive; removed before packaging
  (all three are already covered by `.gitignore` and are regenerated by
  `npm install` / `npm run build`).
- No ESLint config or `eslint` package exists in the project despite a
  `"lint": "eslint ."` script in `package.json` — this is a **pre-existing
  gap**, not introduced by this change. See Known Limitations.

## What was integrated (base implementation preserved)

### 1. `src/components/charts/DonutChart3D.tsx` (new)
Base: uploaded `@react-three/fiber` 3D donut (ExtrudeGeometry slices, bevels,
studio lighting, `<Html>` overlay labels, `OrbitControls`).

Refactored only for compatibility:
- Removed the component's internal `fetch('YOUR_FASTAPI_BACKEND_URL_HERE')`
  call and its own loading state — it now receives `data: {name, value, color}[]`
  as a prop, sourced from the dashboard's existing `usePurchaseDistribution`
  query, so it participates in the same 60s auto-refresh / filter pipeline as
  every other chart and has zero hardcoded data.
- The original's per-plant-name hardcoded label offsets (`if (item.name ===
  'Solar') ...`) were replaced with a generic rule (push small slices outward
  based on rank/percentage) so the component works for any plant-type mix the
  sheet returns, not just the 5 sample categories.
- Wrapped in `React.Suspense` + `React.memo` for safe lazy geometry
  computation and to avoid unnecessary re-renders.

### 2. `src/components/charts/EnergySunburstChart.tsx` (new)
Base: uploaded SVG sunburst (dark radial-gradient panel, 3D `rotateX/rotateZ`
tilt, glossy ring gradients, drop-shadow filter, counter-rotated flat text
overlay, center total summary) plus the label/leader-line and gradient-ring
patterns described in `prompt.md` Parts 5–7.

Refactored only for compatibility:
- The uploaded version hand-authored fixed SVG `<path d="...">` arcs and
  percentage-based label positions for one specific dataset (Thermal 82.4%,
  Solar 5.9%, ...). That cannot reflect live sheet data, so the arc/label
  geometry was rewritten as a generic two-ring sunburst calculator
  (`annularSectorPath`, angle/radius math) driven entirely by the
  `usePurchaseSunburst` rows (`ppa_category` → inner ring, `plant_type` →
  outer ring, angularly nested under its parent category — a true sunburst,
  not independent pies).
- Kept the visual language from the source: dark glass panel, gradient rings,
  drop shadow, 3D tilt + counter-rotated labels, center total card.
- Added simple label-collision avoidance (sort by side/vertical position,
  enforce minimum gap) and dashed leader lines for slices under 8%, per the
  "Part 7" guidance in `prompt.md`, kept intentionally lightweight rather
  than a full drill-down/breadcrumb engine (see Known Limitations).
- `React.memo`-wrapped; all geometry/label math is `useMemo`-cached and only
  recomputes when the underlying rows or palette change.

### 3. `src/pages/dashboard/PowerPurchaseDashboard.tsx`
- Added one new chart row ("Energy Mix — 3D Donut (Premium)" and "Energy
  Sunburst — Enterprise") directly below the existing Plotly Treemap/Sunburst
  row. **Nothing existing was removed or altered** — the original Plotly pie
  and Plotly sunburst stay in place, so no existing functionality is broken.
- Added one `useMemo` (`donut3DData`) that maps the existing `distribution`
  query result into the shape the new donut expects.

## Follow-up: dashboard trimmed to only the two premium charts

Per a follow-up request, `PowerPurchaseDashboard.tsx` was simplified further:
KPI row and filters stay as-is, but **all other chart cards were removed** —
Monthly Trend, the old Plotly pie ("Energy by Plant Type"), Treemap, the old
Plotly Sunburst, Sankey, Bubble, Top 10, Waterfall, Heatmap, Polar, and the
Executive Insights list are no longer rendered on this page. Only **"Energy
Mix — 3D Donut (Premium)"** and **"Energy Sunburst — Enterprise"** remain.

- The now-unused React Query hooks (`usePurchaseTrend`, `usePurchaseTreemap`,
  `usePurchaseSankey`, `usePurchaseBubble`, `usePurchaseTop10`,
  `usePurchaseWaterfall`, `usePurchaseHeatmap`, `usePurchasePolar`,
  `usePurchaseInsights`) and the `react-plotly.js` import were removed from
  this page's imports. The hooks themselves are untouched in
  `src/api/purchaseApi.ts` and the backend endpoints are untouched — nothing
  was deleted from the API layer, only unused from this one page, so they're
  still available if you want to bring any of them back later.
- Rebuilt and reverified: `tsc -b` and `vite build` both pass with 0 errors
  after this trim.



1. **ESLint is not configured** in the uploaded project (no `eslint` package,
   no config file) even though `package.json` has a `lint` script. This
   predates this change. To satisfy the "0 ESLint errors" requirement
   properly, ESLint 9 flat-config + `typescript-eslint` + `eslint-plugin-react-hooks`
   should be added as a follow-up — out of scope here since it's an
   unrelated tooling gap, not part of the chart integration.
2. The sunburst is intentionally scoped to **two rings** (PPA Category →
   Plant Type) rather than the full four-level hierarchy (PPA Category → Type
   → Plant Type → Plant) mentioned in the reference title. Rendering all four
   levels as static rings gets unreadable past ~20 plants; `prompt.md`'s own
   Part 7 audit recommends the same 4–5 visible level cap and suggests
   click-to-drill-down for further depth. Drill-down/breadcrumb navigation
   was **not** implemented in this pass — the current version is a solid,
   production-safe base to add it to later.
3. The 3D donut chunk (`three` + `@react-three/fiber` + `@react-three/drei`)
   adds ~300 KB gzipped to the bundle. It's isolated into its own manual
   chunk (`three-*.js`) so it doesn't inflate the main bundle, but it does
   increase total download size versus a pure-Plotly dashboard — acceptable
   for an internal enterprise tool, worth knowing about on slow links.
4. Both new components fall back to a plain "No data available" message when
   their query hasn't resolved/returned empty rows, matching the loading
   pattern already used by `ChartCard` elsewhere in the file.
